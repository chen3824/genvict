# 身份凭证

访问阿里云资源时用于验证身份的凭据，分为**人员凭证**（登录密码 + [[RAM 用户#MFA|MFA]]）与**程序凭证**（[[身份凭证#AccessKey|AccessKey]] 或 STS 临时凭证）。

## AccessKey

- 长期有效的程序访问凭证（AccessKey ID + AccessKey **Secret**），用于调用阿里云 API。
- **Secret 仅在创建时显示一次**，不支持后续查看，必须立即保存（可下载 CSV）。
- 泄露会威胁该账号下全部资源安全。

安全要点（来源 §5.2/5.3）：
- 不给主账号建 AccessKey；**优先使用 STS Token 临时凭证**替代永久 AccessKey。
- 一个 AK 只用于一个应用的一个环境（开发/测试/生产独立），不共用。
- 严禁明文硬编码到代码库，用环境变量或 KMS。
- 设置闲置时长（建议 365 天内，推荐 90 天）、禁闲置 AK、定期轮转、用 ActionTrail 监控。

## STS 临时凭证（推荐）

- 通过 RAM 角色 `AssumeRole`/STS 获取，**超过角色最大会话时间后自动失效**（通常小时级）；泄露可利用窗口极小。
- 优先"无 AK"方案：ECS 实例角色、容器/函数计算角色扮演，彻底避免暴露 AK。
- 适合跨账号访问、CI/CD 任务、第三方运维、临时调试等短期场景，到期自动失效、无需手动撤销。

## MFA

- 多因素认证，密码之外的第二道防线；即使密码泄露也能阻挡非法登录。
- 控制台登录用户建议强制启用（必需绑定 MFA 设备）。

## 管理铁律（来源 §七）

1. 不要泄露或日常使用主账号密码。
2. RAM 用户创建后及时保存登录密码与 AK，页面关闭后部分凭证无法再次获取。
3. 长期凭证最小化，短期权限用角色+STS。
