# 权限策略

一组访问权限的集合，是 [[RAM 用户]] 是否有权访问资源的判定依据。新用户的 RAM 用户默认无任何权限，必须授权后才能在授权范围内访问资源。

## 类型

- **系统策略**：阿里云预设的常用权限集，如 `AliyunECSReadOnlyAccess`、`AliyunOSSFullAccess`；`AdministratorAccess`、`AliyunRAMFullAccess` 是**高风险**策略，仅必要时授予并审慎监控。
- **自定义策略**：无法用系统策略满足精细化授权时创建，用于限定指定 `Resource`、操作（`Action/NotAction`）、条件（`Condition`），实现最小权限。

## 授权范围

- **账号级别**：在账号内全部资源生效，适合通用授权。
- **资源组级别**：仅在指定资源组内生效；此权限的 RAM 用户登录后须把资源范围切换为对应资源组才能访问。

## 授权方式

- 以用户为中心：身份管理 > 用户 > 新增授权。
- 以权限为中心：权限管理 > 授权 > 新增授权。
- **推荐用用户组统一授权**：把职责相同的用户加入用户组，为用户组授权；用户组策略不占用个人策略配额，更易维护。
- 实际生效权限 = 个人权限 ∪ 继承用户组的权限。

## 配额与常见问题

- 每位 RAM 用户的系统策略与自定义策略各有独立上限（默认各 20 条），超出报错 `LimitExceeded.User.Policy`。
- 解决：合并/清理冗余策略、用用户组授权、或到配额中心申请提升。

## 最小权限原则（来源 §5.4）

仅授予完成既定任务所必需的最少权限：
- 非管理员避免直接授予 `AdministratorAccess` 等过大策略；用自定义策略把 `Resource` 限定到具体实例 ID。
- 可通过 `NotAction` / 显式拒绝 `bss:*`、`bssapi:*` 等排除费用相关操作。
- 定期审查（"治理检测""访问分析"）识别 90 天未使用 AK 与过度授权身份。

### 示例：只显示原价、屏蔽优惠折扣

对指定 RAM 用户加一条自定义策略，`Deny` `bss:QueryPrice`，购买页/续费页/购物车/价格计算器/API 询价只显示原价，不影响下单：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Deny",
      "Action": "bss:QueryPrice",
      "Resource": "*"
    }
  ]
}
```

创建路径：权限管理 > 权限策略 > 创建权限策略（脚本编辑），再经"身份管理 > 用户 > 新增授权"绑定到目标用户。立即生效、无需重新登录；只屏蔽价格回显，不拦截下单动作。来源：[[RAM子账号价格与财务托管工单]]。

> 付费统一由"结算关系"控制（[[结算关系与财务托管]]），不是 RAM 权限。

## 临时权限

短期/跨账号场景优先创建具备所需权限的 RAM 角色，通过 [[身份凭证#STS 临时凭证|AssumeRole/STS]] 获取临时凭证，到期自动失效。
