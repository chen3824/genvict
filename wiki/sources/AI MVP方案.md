# AI MVP方案 — 来源摘要

> 本页是 `raw/AI共创/05《AI MVP方案 V1.0》.md` 的摘要页。原件不可修改，一切主张以原件为准。

## 这份来源讲什么

「AI共创工作体系」**模板 05**（阶段05，Stage Gate 1 → MVP → Stage Gate 2）。将已通过 POC 验证的 AI 能力收敛成一个真正可使用的最小业务闭环。核心问题：**用户能否借助这个 AI 能力，独立完成一次真实业务任务？**

## 关键内容一览

- **MVP 定义纠偏**：不是"功能最少的产品"，而是"用最小产品范围完整跑通一个真实业务价值闭环"。
- **三条原则**：① 只做一个核心价值；② 必须有完整业务闭环（用户→输入业务任务→AI 处理→AI 输出→人工确认/修改→业务最终交付，"只生成一段文字"不算 MVP）；③ 减少的是非核心价值功能，不是核心功能。
- **AI 介入点三级标注**：✓介入 / △辅助 / ✕人负责；**人机协作边界：AI 负责"生产和辅助判断"，人负责"最终业务责任"**——客户承诺、商务报价、合规等必须人工确认。
- **功能优先级判定规则（防膨胀核心规则）**：对每个功能问"没有它，用户还能不能完成一次核心任务？"→ 不能 = **P0**（必须有）；可以但体验下降 = **P1**；锦上添花 = **P2**（暂不做，须写暂缓原因）。
- **质量控制 5 步**：AI 生成 → 来源验证 → 规则检查 → 人工确认 → 正式使用（AI 输出不能直接进业务）。
- **指标体系 4 类**：Task Completion / AI Quality / Efficiency / User Experience。
- **三轮测试制**：内部测试 → 业务专家测试（1~3 名）→ 真实用户测试。
- **5 个常见错误**：把 POC 直接产品化、功能不断增加、没有真实用户、只测 AI 不测业务、**没有明确"不做什么"（Out of Scope 是最重要文档之一）**。
- **Gate 2 决策**：🟢 GO → Pilot / 🟡 ITERATE / 🔴 KILL。
- **AI MVP CANVAS 一页纸**：项目/核心用户/核心问题/VALUE/CORE WORKFLOW/P0 清单/NOT NOW/AI/SUCCESS/DECISION。
