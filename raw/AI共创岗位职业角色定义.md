# AI共创岗位职业角色定义

## 一、角色定位

### 核心定义

AI共创不是单纯的AI产品经理、AI运营、FDE或AI工具推广人员，而是一个：

> **连接AI能力与业务场景，以业务价值为目标，推动AI从“能力”走向“真实使用”和“业务结果”的业务AI落地角色。**

核心使命：

> **发现业务中的AI机会 → 组织跨团队共创 → 验证AI价值 → 推动业务采用 → 衡量实际效果 → 沉淀可复制的AI能力。**

---

## 二、角色的核心价值

### 1. AI能力与业务之间的连接器

将：

- LLM
- Agent
- RAG
- Workflow
- MCP
- AI工具
- 企业AI底座

转化为：

- 业务场景
- 工作流
- 员工生产力
- 业务价值

---

### 2. 业务AI机会的发现者

主动进入业务，而不是等待业务提出“AI需求”。

重点寻找：

- 高频工作
- 重复工作
- 信息密集型工作
- 知识密集型工作
- 决策辅助工作
- 高成本工作
- 高错误率工作

---

### 3. AI项目的共创推动者

协调：

- 业务负责人
- 一线员工
- AI Champion
- AI/技术团队
- IT
- 数据团队
- 管理层

共同完成AI项目落地。

---

### 4. AI价值验证者

不以：

> “上线了多少AI项目”

作为核心成果。

而关注：

> **AI是否真正被使用，以及是否产生业务价值。**

---

### 5. AI能力沉淀者

将成功项目沉淀为：

- AI工具
- Prompt
- Workflow
- Agent
- Knowledge Base
- SOP
- 最佳实践
- Case Study
- 方法论

形成公司的AI能力资产。

---

## 三、角色边界

### AI共创团队负责

- 场景发现
- 业务诊断
- AI方案设计
- POC推动
- MVP共创
- Pilot推动
- Adoption推动
- 效果衡量
- 能力沉淀
- 方法论建设
- AI能力推广

### 业务Owner负责

- 业务问题
- 业务目标
- 业务流程
- 资源协调
- 员工使用
- 最终业务结果

### AI/技术团队负责

- 模型
- 平台
- 工程开发
- 数据
- 系统集成
- 稳定性
- 技术安全

### 管理层负责

- 战略方向
- 资源
- 优先级
- 组织机制
- 重大项目决策

---

## 四、最终角色目标

不是：

> “帮公司做更多AI项目。”

而是：

> **让公司越来越多的业务流程具备AI能力，并持续产生可衡量、可复制的业务价值。**

---

## 五、英文名词缩写备注

> 本文档中出现的英文名词/缩写的含义说明。

| 名词/缩写 | 全称 | 含义 |
|-----------|------|------|
| AI | Artificial Intelligence | 人工智能 |
| FDE | Forward Deployed Engineer | 前沿部署工程师：驻场贴近业务/客户、负责AI能力落地的工程师 |
| LLM | Large Language Model | 大语言模型，如 GPT、DeepSeek 等 |
| Agent | — | 智能体：能自主规划、调用工具完成任务闭环的 AI 单元 |
| RAG | Retrieval-Augmented Generation | 检索增强生成：先检索资料再生成回答，减少幻觉 |
| Workflow | — | 工作流：将多步骤任务编排成固定流程 |
| MCP | Model Context Protocol | 模型上下文协议：AI 与外部系统/工具连接的统一标准 |
| AI Champion | — | AI 倡导者：业务侧推动 AI 落地与使用的种子用户 |
| IT | Information Technology | 信息技术：企业内部的技术支持/信息化部门 |
| Prompt | — | 提示词：指导 AI 完成任务的输入指令 |
| Knowledge Base | — | 知识库：组织化的知识沉淀与检索库 |
| SOP | Standard Operating Procedure | 标准操作规程 / 标准化作业流程 |
| Case Study | — | 案例研究：对成功/失败案例的复盘总结 |
| POC | Proof of Concept | 概念验证：小范围论证某方案是否可行 |
| MVP | Minimum Viable Product | 最小可行产品：以最小成本验证价值的产品形态 |
| Pilot | — | 试点：正式推广前的小范围试运行 |
| Adoption | — | 采用：业务员工对新系统/工具实际使用与接受 |
| Owner | — | 负责人：对某项工作负最终责任的角色 |
