## 一、认识 RAM 用户

### 1.1 什么是 RAM 用户

RAM 用户是访问控制（RAM）中的一种**实体身份类型**，有确定的身份 ID 和身份凭证，通常与某个确定的人或应用程序一一对应。当企业存在多用户协同访问云资源的场景时，可以创建多个 RAM 用户并按需分配最小权限，避免多用户共享阿里云账号（主账号）密码或 AccessKey，从而降低安全风险。

RAM 用户的核心特点：

1. RAM 用户由阿里云账号（主账号）或具有管理员权限的其他 RAM 用户、RAM 角色创建。
2. RAM 用户创建成功后归属于该阿里云账号，**不是独立的阿里云账号**。
3. RAM 用户不拥有资源，不能独立计量计费，由所属的阿里云账号统一付费。
4. RAM 用户必须在获得授权后，才能登录控制台或使用 API 访问阿里云账号下的资源。
5. RAM 用户拥有独立的登录密码或 AccessKey。
6. 一个阿里云账号下可以创建多个 RAM 用户，分别对应企业内的员工、系统或应用程序。
7. RAM 用户创建后本身不产生费用。

### 1.2 RAM 用户与阿里云主账号的区别

| 对比项  | 阿里云主账号               | RAM 用户             |
| ---- | -------------------- | ------------------ |
| 账号性质 | 独立的阿里云账号             | RAM 中的实体身份，不是独立账号  |
| 身份角色 | 资源拥有者，拥有全部资产和最高权限    | 资源和服务的使用者，权限由主账号授予 |
| 资源归属 | 拥有云资源                | 不拥有资源，资源归属主账号      |
| 计费方式 | 独立计量计费               | 不能独立计费，由主账号统一付费    |
| 默认权限 | 全部权限，不可限制            | 默认无任何权限，需主账号授权     |
| 身份凭证 | 主账号登录密码、AccessKey 等  | 独立的登录密码或 AccessKey |
| 使用建议 | 仅用于授权、付费、账号管理等关键管理操作 | 用于日常开发、运维、部署等      |

阿里云主账号类似于 Linux 系统中的 `root` 用户，权限极大但不适合日常使用。如果主账号泄露，会带来严重的安全隐患。需要授权其他人访问阿里云资源时，不要直接泄露主账号及密码，而应创建 RAM 用户并为其分配必要权限。

### 1.3 RAM 用户的创建途径

按创建方式划分，RAM 用户分为三类：

1. **手动创建**：在 RAM 控制台手动创建。适用于为员工创建独立登录账号、为应用程序创建独立访问凭证、按角色/部门/业务分配权限的场景。
2. **SCIM 同步**：通过 SCIM 协议从企业身份提供商（IdP）同步创建。适用于企业已有统一身份系统、需要将内部账号同步到阿里云 RAM 的场景。此类用户**不支持手动删除**。
3. **云 SSO 同步**：通过云 SSO 的 RAM 用户同步功能创建。此类用户必须通过云 SSO 登录，不能直接用 RAM 用户名密码登录；删除同步任务后才能手动删除保留的 RAM 用户。

### 1.4 按访问方式划分：控制台登录用户与 API 调用用户

虽然可以为 RAM 用户同时设置控制台登录密码和 API 调用的 AccessKey，但出于安全考虑，**官方建议针对不同用途的 RAM 用户仅设置一种登录方式**，并将人员用户和应用程序用户分离。

- **控制台登录用户**（适用于企业员工）：启用控制台登录、设置密码强度与登录密码、按需启用多因素认证（MFA）。若已启用用户 SSO，也可不开启控制台登录，用户通过 SSO 方式登录控制台。
- **API 调用用户**（适用于应用程序、脚本、自动化系统）：为 RAM 用户创建 AccessKey，使用 AccessKey 调用阿里云 API，不必设置控制台登录密码。

### 1.5 典型使用场景

1. **多用户协同访问云资源**：为每个员工创建独立的 RAM 用户，而不是共享主账号密码。
2. **权限分离与最小权限管理**：管理员拥有管理权限，开发人员只能访问开发相关资源，运维人员只能管理特定资源，财务人员只能查看账单，应用程序只能访问特定 API 或资源。
3. **避免共享主账号 AccessKey**：为不同用户或应用创建独立 RAM 用户和 AccessKey，降低泄露风险。
4. **企业统一身份管理**：通过 SCIM 同步或云 SSO 同步方式与企业身份系统打通。

## 二、创建 RAM 用户

### 2.1 前提条件

- 已拥有阿里云主账号（RAM 用户在主账号下创建和管理）。
- 使用以下身份之一登录 RAM 控制台（https://ram.console.aliyun.com/）：
  - 阿里云账号（主账号）；
  - 拥有 RAM 管理员权限（系统策略 `AliyunRAMFullAccess`）的 RAM 用户。
- 官方建议：创建 RAM 用户前，先为主账号设置一个易记的**账号别名**（默认域名），替代 16 位数字的账号 ID，以简化 RAM 用户的登录操作。

### 2.2 通过控制台创建 RAM 用户

操作步骤：

1. 使用主账号或 RAM 管理员登录 RAM 控制台。
2. 在左侧导航栏，选择 **身份管理 > 用户**。
3. 在"用户"页面，单击 **创建用户**。
4. 在"用户账号信息"区域填写基本信息：

| 参数 | 是否必填 | 说明 |
| --- | --- | --- |
| 登录名称 | 必填 | 用于 RAM 用户登录；可包含英文字母、数字、半角句号 `.`、短划线 `-`、下划线 `_`，最多 64 个字符 |
| 显示名称 | 选填 | 用于展示，最多 128 个字符或汉字 |
| 标签 | 选填 | 输入标签键和标签值，便于后续基于标签管理用户 |
| 安全手机 | 选填 | 填写手机号，首次绑定后需通过短信验证激活 |

5. 如需批量创建，单击 **添加用户** 即可一次创建多个 RAM 用户。
6. 配置访问方式（见 2.3）。
7. 单击 **确定**，按提示完成安全验证（手机号验证或扫脸验证），验证通过后提示创建成功。

此外，RAM 控制台"概览"页还提供 **快速开始** 场景化创建能力（如"审计管理员"等预置场景），会自动完成"创建用户 → 创建用户登录配置 → 创建用户组 → 添加用户到用户组 → 创建自定义策略 → 为用户组绑定权限策略"的流程，适合按角色快速配置。快速创建的 RAM 用户后续仍可在控制台修改配置，且默认要求首次登录重置密码、绑定 MFA。

### 2.3 配置访问方式

出于账号安全，**建议只选择以下访问方式中的一种**：

**（1）控制台访问（给员工使用）**

勾选"控制台访问"后配置：

- **控制台密码**：可选择自动生成密码或自定义密码；自定义密码必须满足密码复杂度规则（参见"设置 RAM 用户密码策略"）。
- **需要重置密码**：选择用户下次登录时是否需要重置密码。
- **MFA 多因素认证**：账号默认设置为强制所有用户登录时必须使用 MFA；启用 MFA 后，RAM 用户首次登录控制台时需要绑定 MFA 设备。

**（2）使用永久 AccessKey 访问（给程序使用）**

勾选"使用永久 AccessKey 访问"后，系统会自动为该 RAM 用户生成 AccessKey ID 和 AccessKey Secret。

> **重要**：RAM 用户的 AccessKey Secret 只在创建时显示，不支持后续查看，请务必立即下载或复制保存。AccessKey 是长期有效的程序访问凭证，泄露会威胁该账号下所有资源的安全，建议优先采用 STS Token 临时凭证方案。

创建成功后，页面会展示每个用户的登录密码、AccessKey 等信息，**页面关闭后将无法再次获取**，请及时保存（可下载 CSV 文件），并可继续"添加到用户组"或"添加权限"。

### 2.4 通过 OpenAPI 创建 RAM 用户

**创建控制台用户**：

1. 调用 `GetDefaultDomain` 获取账号默认域名（格式 `<AccountAlias>.onaliyun.com`）。
2. 调用 `CreateUser` 创建用户，传入 `UserPrincipalName`（登录名称，格式 `<username>@<AccountAlias>.onaliyun.com`）和 `DisplayName`（显示名称）。
3. 调用 `CreateLoginProfile` 创建控制台登录配置，关键参数：`Password`（需满足密码强度策略，可用 `GetPasswordPolicy` 查询）、`MFABindRequired`（建议设为 `true` 强制绑定 MFA）、`Status`（保持默认 `Active`）。

**创建程序用户**：

1. 调用 `GetDefaultDomain` 获取默认域名。
2. 调用 `CreateUser` 创建用户。
3. 调用 `CreateAccessKey`，传入 `UserPrincipalName` 即可创建 AccessKey。返回结果中的 `AccessKeySecret` 仅在本次返回中提供，无法后续查询，必须立即安全保存。

### 2.5 创建后的后续步骤

1. **为 RAM 用户授权**：新创建的 RAM 用户没有任何权限，必须授权后才能访问相应云资源。
2. **使用 RAM 用户登录控制台或调用 API**。
3. （可选）修改 RAM 用户登录域名、修改 RAM 用户基本信息。

## 三、为 RAM 用户授权

新创建的 RAM 用户默认无任何权限，必须为其授予权限后，才能在授权范围内访问和管理阿里云资源。授权应遵循**最小权限原则**。授权后权限通常立即生效，无需等待或重新登录。

### 3.1 权限策略类型

权限策略是一组访问权限的集合，分为两类：

- **系统策略**：阿里云预设的常用权限集。例如：

| 策略名称 | 说明 |
| --- | --- |
| `AdministratorAccess` | 管理所有阿里云资源的权限（高风险，谨慎授予） |
| `AliyunRAMFullAccess` | RAM 完全管理权限（高风险，谨慎授予） |
| `AliyunECSReadOnlyAccess` | 只读访问云服务器 ECS |
| `AliyunECSFullAccess` | 管理云服务器 ECS 的权限 |
| `AliyunOSSFullAccess` | 管理对象存储 OSS 的权限 |

- **自定义策略**：系统策略无法满足精细化授权需求时，可先创建自定义权限策略再授权。适用于限制指定资源、限制某些操作、排除费用/RAM 管理等高风险权限、按业务场景定制最小权限。

### 3.2 授权范围

- **账号级别**：权限在当前阿里云账号内全部资源生效，适用于通用授权。
- **资源组级别**：权限仅在指定资源组内生效，适用于多团队共用账号、按资源组隔离权限的场景。注意：被授予资源组级别权限的 RAM 用户登录控制台后，必须在顶部导航栏将资源范围切换到被授权的资源组，才能正常访问该资源组内的资源。

### 3.3 控制台授权步骤

RAM 控制台提供两个授权入口：

- **入口一（以用户为中心）**：身份管理 > 用户 → 找到目标 RAM 用户 → 单击操作列的 **新增授权**（可勾选多个用户批量授权）。
- **入口二（以权限为中心）**：权限管理 > 授权 → 单击 **新增授权**，手动选择授权主体，可统一查看和管理授权关系。

在"新增授权"面板中依次配置：

1. **选择资源范围**：账号级别或资源组级别。系统会自动标识高风险系统策略（如 `AdministratorAccess`、`AliyunRAMFullAccess`），请谨慎授予。
2. **选择授权主体**：目标 RAM 用户（从"用户"页面发起时自动选定）。
3. **选择权限策略**：系统策略可按产品名（如 ECS、OSS）、权限级别（ReadOnly、FullAccess）或完整策略名模糊搜索；自定义策略需先创建再授权。
4. **填写备注**（可选）：建议填写授权原因，便于审计回溯。
5. 单击 **确认新增授权**，确认绑定结果后关闭。

**批量授权建议**：当需要为多名职责相同的 RAM 用户授予相同权限时，建议将用户加入同一用户组（身份管理 > 用户组），为用户组统一授权。用户组策略不占用用户个人的策略配额，更易维护。

### 3.4 查看 RAM 用户的权限

- 路径：身份管理 > 用户 → 单击目标用户名称 → **权限管理**，可查看"个人权限"和"继承用户组的权限"。
- 用户实际生效权限 = 个人权限 + 继承用户组的权限（两者并集）。
- 注意："权限管理 > 授权"页面展示的是**授权操作记录**（谁在什么时间给谁授予了什么策略），不是用户当前权限快照。
- 可通过用户详情的"权限审计"和 RAM 概览页的"访问分析"查看最近访问时间、权限是否闲置、是否存在过度授权。
- OpenAPI：调用 `ListPoliciesForUser` 查询指定用户账号级授权列表（不能查询资源组级别的授权）。

### 3.5 移除 RAM 用户的权限

撤销前建议先在"权限审计"或"访问分析"中确认策略最近使用情况，避免误删仍在使用的权限。

- **从"用户"页面移除**：身份管理 > 用户 → 用户详情 → 权限管理 → 在个人权限中筛选目标策略 → 单击 **解除授权** → 确认授权主体和权限策略后解除。
- **从"授权"页面移除**：权限管理 > 授权 → 找到目标记录 → 单击 **解除授权**（支持选中多条记录批量移除）。
- **OpenAPI**：调用 `DetachPolicyFromUser` 撤销指定权限。

### 3.6 OpenAPI 授权常用 API 汇总

| 操作 | API |
| --- | --- |
| 创建自定义策略 | `CreatePolicy` |
| 绑定自定义策略到 RAM 用户 | `AttachPolicyToUser`（`PolicyType=Custom`） |
| 绑定系统策略到 RAM 用户 | `AttachPolicyToUser`（`PolicyType=System`） |
| 资源组级别授权 | `AttachPolicy`（资源管理 ResourceManager） |
| 查询用户账号级授权列表 | `ListPoliciesForUser` |
| 移除 RAM 用户权限 | `DetachPolicyFromUser` |
| 获取临时凭证/扮演角色 | `AssumeRole`（STS） |

### 3.7 策略数量限制

每个 RAM 用户可绑定的系统策略和自定义策略各有独立数量上限（默认各 20 条），超出后将无法继续添加，报错 `LimitExceeded.User.Policy`。解决方法见 6.2。

## 四、RAM 用户登录

### 4.1 账号别名与默认域名

RAM 用户默认登录名称格式为 `<UserName>@<AccountAlias>.onaliyun.com`，其中 `<AccountAlias>.onaliyun.com` 是主账号的**默认域名**，`<AccountAlias>` 为账号别名（默认值为主账号 ID）。

设置/修改默认域名的步骤：

1. 使用主账号登录 RAM 控制台。
2. 左侧导航栏选择 **设置 > 账号域名**。
3. 单击"默认域名"后的 **编辑**，修改默认域名。

注意事项：只有主账号或具有 RAM 管理员权限的 RAM 用户才能设置或修改账号别名；别名一经设置即刻生效；所有新生成的 RAM 用户登录名将默认使用该别名。

### 4.2 登录链接

RAM 用户登录页面与主账号登录页面不同，有两种登录方式：

- **通用登录链接**：https://signin.aliyun.com/login.htm ，在页面底部"其他方式"区域选择"RAM 用户"。
- **专属登录链接**：`https://signin.aliyun.com/{默认域名}/login.htm`，可在 RAM 控制台 **概览 > 基础信息 > 登录地址** 处复制。使用专属链接可避免重复输入默认域名。

### 4.3 登录步骤与首次登录

1. 在 RAM 用户登录页面输入 RAM 用户名，单击"下一步"。
2. 输入登录密码，单击"登录"。
3. 首次登录时：
   - 若要求绑定 MFA，需要绑定 MFA 设备，后续登录需输入 MFA 验证码；
   - 若创建时配置了"需要重置密码"（通过"快速开始"创建的用户默认要求重置密码），登录后会弹出密码重置对话框，输入并确认新密码后完成重置，再进入控制台。

登录成功后，可将鼠标悬停在控制台右上角头像查看当前身份信息（登录邮箱、账号 ID、当前身份、企业别名、主账号 ID）。

## 五、安全最佳实践（官方）

以下内容整理自官方文档《身份与权限的最佳实践》，围绕人员身份、程序身份、权限管理三个维度展开。

### 5.1 人员身份最佳实践

1. **避免使用主账号进行日常运维**：创建一个拥有管理员权限的 RAM 用户专门用于日常管理，主账号仅在必要时使用，并妥善保管主账号密码、MFA 等凭证；为组织内每一位成员创建独立的 RAM 用户并授权；为主账号启用 MFA 进行安全加固。
2. **建立更安全的登录机制**：通过 RAM 用户密码策略提升密码复杂度（最小长度、复杂度要求、有效期建议最长 90 天、重试次数限制）；强制启用 MFA——MFA 是密码之外的第二道防线，即使密码泄露也能有效阻挡非法登录。
3. **实现人员身份统一认证（SSO）**：通过单点登录将身份认证交由企业 IdP（如 Active Directory、Okta）管理，支持 SAML 2.0、OIDC 协议；人员入离职、权限变更在 IdP 中集中完成。若企业使用资源目录管理多个阿里云账号，更推荐使用云 SSO 实现多账号统一身份权限管理。

### 5.2 程序身份最佳实践

程序身份代表应用程序或服务，通过 API 以非交互式方式访问云资源。管理核心：**杜绝永久凭证，全面转向有时效的临时凭证**。

1. **优先使用临时凭证 STS Token**：永久 AccessKey 在手动删除前永远有效，泄露风险持续存在；通过 RAM 角色扮演获取的 STS Token 在超过角色最大会话时间后自动失效（通常为小时级），即使泄露，被利用的时间窗口也极小。优先使用无 AK 方案获取 STS Token，如 ECS 实例角色扮演、容器实例角色扮演、函数计算角色扮演，彻底避免暴露 AccessKey。
2. **必须使用 AccessKey 时的原则**：
   - 避免使用主账号 AccessKey，替换为具有适当权限的 RAM 用户 AccessKey；
   - 一个 AccessKey 只用于一个应用的一个环境（开发、测试、生产分别独立），避免共用；
   - 为 AccessKey 所在的 RAM 用户授予该场景下的最小权限策略；
   - **严禁将 AccessKey 明文硬编码到代码库**，建议通过系统环境变量或 KMS 凭据管理；
   - 配置网络访问策略，限制 AccessKey 只能从特定 IP 地址访问；
   - 设置 AccessKey 最大闲置时长（建议 365 天以内，推荐 90 天），闲置 AccessKey 及时禁用并回收；
   - 通过操作审计 ActionTrail 监控 AccessKey 使用情况，及时发现异常行为。

### 5.3 AccessKey 安全管理要点汇总

- 强烈建议不要给阿里云主账号创建 AccessKey。
- 减少创建永久 AccessKey，优先采用 STS Token 临时凭证方案。
- 妥善保管 AccessKey ID 和 AccessKey Secret，不要随意分享，不要记录在公开文档中。
- AccessKey Secret 仅在创建时显示一次，必须立即安全保存。
- AccessKey 不再使用时应及时禁用；定期轮转（一个 RAM 用户启用一把 AccessKey，另一把仅用于轮转）。
- 为 RAM 用户仅授予必要的最小权限。

### 5.4 权限管理最佳实践

1. **授予最小必要权限**：仅授予完成既定任务所必需的最少权限。非管理员场景避免直接使用 `AdministratorAccess` 等权限过大的系统策略；通过自定义策略明确指定 `Resource`（可操作的资源）、`Action/NotAction`（允许或拒绝的操作）、`Condition`（授权条件）。示例：
   - 管理指定 ECS 实例：自定义策略中将 `Resource` 限定为具体实例 ID，而不是授予 `AliyunECSFullAccess`；
   - 授予除费用外的所有权限：自定义策略中显式拒绝 `bss:*`、`bssapi:*`、`efc:*` 等费用相关操作。
2. **定期审查权限**：通过 RAM 概览页"治理检测"识别 90 天内未使用的 AccessKey 和闲置 RAM 用户；通过"访问分析"的过度授权分析器识别超出实际使用范围的过度授权身份。
3. **通过 RAM 用户组简化权限管理**：根据岗位职责创建用户组（如网络管理员、应用开发、运维人员、安全管理员），按职责为用户组授权，不建议直接将权限策略附加到单个 RAM 用户。
4. **多账号环境设置权限边界**：基于资源目录的管控策略限制成员账号内的 RAM 身份权限范围（先管控策略检查，再账号内 RAM 权限检查）；绑定管控策略前先小范围测试，确认有效后再绑定到全部目标节点。
5. **临时授权优先使用 RAM 角色**：跨账号访问、临时 CI/CD 任务、第三方运维、临时调试等短期场景，建议创建具备所需权限的 RAM 角色，通过 `AssumeRole`/STS 获取临时凭证，到期自动失效，无需手动撤销。

## 六、常见问题与排查

### 6.1 RAM 用户访问资源时提示"权限不足"如何排查？

进入 RAM 控制台 **权限管理 > 权限诊断**，将权限错误响应中的诊断密文（`AccessDeniedDetail.EncodedDiagnosticMessage`）或 Request ID 粘贴到诊断框，单击"开始诊断"。系统会反向解析出本次拒绝的具体原因（命中的策略、条件、显式拒绝等），帮助快速定位问题。更多方法参见官方文档《如何排查无权限的访问错误》。

### 6.2 授权时报错 `LimitExceeded.User.Policy` 怎么办？

原因是该 RAM 用户绑定的策略数量已达到配额上限（系统策略和自定义策略默认各 20 条）。解决方法：

1. **优化现有策略**：移除重复或不再需要的策略（例如 `AliyunECSFullAccess` 已包含 `AliyunECSReadOnlyAccess` 的全部只读能力，无需重复授予）；将多个系统策略合并为一个自定义策略。
2. **使用用户组授权**：将职责相同的 RAM 用户加入同一用户组统一授权，用户组策略不占用用户个人的策略配额。
3. **申请提升配额**：前往配额中心（https://quotas.console.aliyun.com/）搜索"一个 RAM 用户可以绑定的系统策略/自定义策略个数"，提交配额提升申请。

### 6.3 RAM 用户如何查看自己拥有的权限？

出于安全考虑，RAM 用户默认无法直接查看自己被授予的完整权限策略列表。可通过"功能试用"（尝试访问所需产品控制台，提示无权限即缺少相应权限）了解权限范围，或联系组织管理员（主账号或拥有 `AliyunRAMFullAccess` 的 RAM 用户）在 RAM 控制台用户详情页查询。

### 6.4 RAM 用户可以购买云产品吗？

可以，但需要为其授予购买产品所需的特定权限。注意：目前不支持为单个 RAM 用户设置独立的消费额度或账单，所有 RAM 用户的消费都计入主账号并由主账号统一支付。

### 6.5 如何为 RAM 用户授予临时、可回收的权限？

不建议为 RAM 用户附加长期生效的临时性策略。推荐创建具备所需权限的 RAM 角色，让 RAM 用户通过 `AssumeRole`/STS 获取有时间限制的临时凭证，到期自动失效、无需手动撤销，适合 CI/CD、跨账号代理、第三方运维等场景。

## 七、关键注意事项汇总

1. 不要直接使用或泄露阿里云主账号和密码；主账号仅用于授权、付费、账号管理等关键管理操作。
2. 为不同人员/系统/应用创建独立 RAM 用户，人员用户和程序用户分离。
3. RAM 用户默认无任何权限，必须授权后才能访问资源；授权遵循最小权限原则。
4. 建议针对不同用途的 RAM 用户仅设置一种访问方式（控制台登录或 AccessKey 二选一）。
5. RAM 用户创建成功后，务必及时保存登录密码和 AccessKey 信息，页面关闭后部分凭据无法再次获取。
6. AccessKey Secret 仅在创建时显示一次；程序访问优先使用 STS Token 临时凭证。
7. 控制台登录用户建议启用 MFA；建议设置账号别名简化登录。
8. 高风险策略（`AdministratorAccess`、`AliyunRAMFullAccess`）仅在必要时授予，并严格审计监控。
9. 定期审计权限，及时清理闲置 RAM 用户、闲置 AccessKey 和过度授权。
10. 临时、短期授权优先使用 RAM 角色 + STS 临时凭证。
11. SCIM 同步创建的 RAM 用户不支持手动删除；云 SSO 同步用户必须通过云 SSO 登录。
